Hack Day の必須機能（[PLAN_04 要件定義書](PLAN_04_要件定義書.md)）が動いた後，時間が余った時や Hack Day 後の追加開発（Kaizen Sprint 等）で取り組む案をまとめる．
着手するときは，内容を PLAN_04 の機能要件に移すか，Issue（`/task-create`）にする．

出典: チームメンバーによるシステム基本設計の検討メモ（2026-10-24）と，それに対する技術面の検討．

## 各案の検討メモ (Notes)

### AI による振り返り (AI Feedback)

- 送るのは**行動ログ（どの場面で何をしたか・かかった時間等の JSON．数 KB）だけ**にする．録画は送らない
- 生成 AI の API キーはブラウザに置けない（提出リポジトリは public で，配信先の GitHub Pages は静的サイトのため）．キーを持つ小さなサーバー関数（Cloudflare Workers 等）を用意し，ブラウザはそこへログを送る
- 体験中は通信しない方針（PLAN_04 の非機能要件）を保つため，送るのは体験の終了後だけにする．通信できない時は，端末内で作る結果表示（PLAN_04 の F7）だけを出す
- 狙える賞: ULS コンサルティング（AI エージェント），ソフトバンク等（[PLAN_03](PLAN_03_審査基準とアワード.md)）

### 機械学習による動作判定 (ML-based Motion Detection)

- 公開データセット（WISDM・UCI HAR）は，スマホを腰やポケットに付けて実際に歩いた時のデータであり，頭に付けてその場で足踏みする本アプリとは波形が大きく異なる．そのまま流用しても精度は期待しにくい
- まずはルールによる判定（[ENV_01](../02_ENV/ENV_01_技術スタック.md)「歩行・しゃがみ判定」）で作り，開発用ページで記録した**自分たちの足踏み・しゃがみのデータ**を貯めておく．精度が足りない場合に，そのデータで小さなモデル（1D-CNN 等）を学習する
- 推論自体は 1 回数 ms で済む見込みだが，ブラウザで動かすための実行環境（TensorFlow.js・ONNX Runtime Web 等）の読み込みが増える

### 体験の録画 (Recording)

- Web では `MediaRecorder` で描画中の画面（canvas）を録画できる
- 立体描画・手の認識と同時に動画の圧縮を行うため，iPhone で 30 fps を保てるかを先に確かめる必要がある
- 録画は端末に一時保存し，送る場合も体験の終了後にまとめて送る（体験中の送信は描画を乱すため）
- 発表用のデモ動画が目的なら，iPhone 標準の画面収録で足りる
