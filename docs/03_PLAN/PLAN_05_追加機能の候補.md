## 各案の検討メモ (Notes)

### 機械学習による動作判定 (ML-based Motion Detection)

- 公開データセット（WISDM・UCI HAR）は，スマホを腰やポケットに付けて実際に歩いた時のデータであり，頭に付けてその場で足踏みする本アプリとは波形が大きく異なる．そのまま流用しても精度は期待しにくい（Issue #49 で切り分け中）
- 代わりに，正解付きの動きの記録（[TEST_01](../06_TEST/TEST_01_動きの記録の取り方.md)．`logs/input/`）を使う．進め方の案:
  1. **事前学習（オフライン）**: 短い区間ごとの特徴（上下の加速度の分散・山の高さ・周期・頭の回転量）から，ロジスティック回帰程度の小さなモデルを作る．係数は TypeScript の定数として持ち，実行環境（TensorFlow.js 等）は読み込まない
  2. **本人への合わせ込み（体験の開始時，端末内）**: キャリブレーション（S1）の立つ・しゃがむ・足踏みの区間のデータで，特徴の基準とモデルのしきい値を本人に合わせる．キャリブレーションの足踏みは 6 歩程度で少ないため，ゼロから学習せず「事前学習したモデルの合わせ込み」にとどめる
  3. **ルールの判定を残す**: データが足りない・時間切れの時は，今のルールの判定に戻す
- 採用の基準: `npm run replay` で今のルールの判定と並べ，「3 人で学習して残りの 1 人で試す」を人数分回して，SPEC_01「判定の安定性」の目安でルールより良い時だけ既定にする
- 前提: キャリブレーションの値を lobby/ ではなく input/ が当てはめる形（SPEC_01「キャリブレーションとの分担」．Issue #58）にしておく

### AI による振り返り (AI Feedback)

- 送るのは**評価と経路（`DrillEvaluation`・`DrillTrack` の JSON．数 KB）と校舎の配置だけ**にする．録画は送らない．生徒の名前等の個人情報は送らない
- 生成 AI の API キーはブラウザに置けない（提出リポジトリは public で，配信は静的サイトのため）．キーを持つ小さなサーバー関数（Cloudflare Pages Functions 等）を用意し，ブラウザはそこへ送る．図面の自動読み取り（ES3）と同じサーバー関数の置き場所を使う
- 体験中は通信しない方針（PLAN_04 の非機能要件）を保つため，送るのは体験の終了後だけにする．通信できない時は，端末内で作る結果表示（PLAN_04 の F8）だけを出す
- 狙える賞: ULS コンサルティング（AI エージェント），ソフトバンク（学び）等（[PLAN_03](PLAN_03_審査基準とアワード.md)）

### クラス全体の結果の集計 (Class Summary)

- 生徒の端末から評価と経路をサーバーに送り，教員の画面で同じ訓練（QR）の結果をまとめて見る．「多くの生徒が火元に近い階段へ向かった」等，訓練の振り返りに使える
- 端末から送るのは体験の終了後だけにする．訓練ごとの ID を QR に含め，生徒の名前は送らず出席番号等にとどめる
- サーバー（保存先・認証）が要るため，「校舎データの保存と共有」と一緒に検討する

### 体験結果の Bluesky 投稿 (Share to Bluesky)

- 狙える賞: Bluesky 賞（Award Day のみ．条件: AT プロトコル／Bluesky API を活用した作品．[PLAN_03](PLAN_03_審査基準とアワード.md)）．スポンサー提供物として API が用意されており，質問は Slack `#support-bluesky`
- 最小の形は，結果画面に「Bluesky で共有」ボタンを置き，投稿文（例: 「理科室が火元の避難訓練で，95 秒で校庭に避難できた．煙の中で低い姿勢もとれた」）を入れた投稿画面を開くだけ．ログインや API キーの管理がアプリ側に要らない
- 利用者が小学生のため，学校の訓練では投稿させず，デモの体験者・保護者向けの機能とする
- AT プロトコルの API で直接投稿する（画像付き投稿・ハッシュタグでの集計等）場合は，ユーザーのログインと認証情報の扱いが要る．秘密情報をブラウザに置かない方針（ENV_01）との兼ね合いを先に決める

### 体験の録画 (Recording)

- Web では `MediaRecorder` で描画中の画面（canvas）を録画できる（旧方針で `src/recording/` を用意した）
- 立体描画・火と煙の描画・手の認識と同時に動画の圧縮を行うため，iPhone で 30 fps を保てるかを先に確かめる必要がある
- 録画は端末に一時保存し，送る場合も体験の終了後にまとめて送る（体験中の送信は描画を乱すため）
- 発表用のデモ動画が目的なら，iPhone 標準の画面収録で足りる

### 図面の自動読み取りの注意点 (Notes on ES3)

ES3 の設計は SPEC_02「配置の下書き」にある．取り組む時の注意点を残す．

- **精度**: きれいな図面ならかなり読めるが，手描きや複雑な図は崩れる．「AI は下書き，人が直す」前提にすれば，エディタがあるので問題にならない
- **縮尺**: 教員が E1 で写真をマス目に合わせた範囲を切り出して渡すため，AI に寸法を推測させなくてよい
- **AI を使わない代わりの案**: 図面の写真を下敷きにしてなぞる（E1・E2）が，そのまま AI を使わない場合の方法になっている
