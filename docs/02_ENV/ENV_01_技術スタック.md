# 技術スタック (Tech Stack)

[PLAN_04 要件定義書](../03_PLAN/PLAN_04_要件定義書.md) を実現するための技術選定と，その理由をまとめる．
バージョンは導入時の最新安定版を使い，`package-lock.json` で固定する（実際に入れたバージョンは環境構築フェーズで ENV_02 に記録する）．

## 方針 (Policy)

- **iPhone の Safari で動くことを最優先**にし，同じ作りのまま Android の Chrome でも動かす
- iPhone の Safari は WebXR に対応していないため，**WebXR は使わない**．左右 2 画面の描画と頭の向きの追従を自前で行う（Android もこの方式で動く）
- サーバーは持たない．**静的サイト**として配信し，体験中は通信無しで動かす（会場の回線対策）
- 判定ロジック（歩行・しゃがみ・シナリオ進行）は描画やブラウザ API から切り離した純粋な TypeScript の関数にし，センサーの記録データでテストできるようにする
- 実装は Claude Code が行うため，選定の基準は人の慣れではなく **Claude が正確に書けるか（情報量・API の安定性），機能と品質，保守性（型・テストのしやすさ）** とする

| 分類 | 採用 | 用途・理由 |

| 言語 | TypeScript | 4 人で並行開発するため，型で関数の受け渡しを揃える |

| 3D 描画 | three.js | 左右 2 画面の描画（`StereoCamera`）・glTF 読み込み・立体音響（`PositionalAudio`）が揃っている．Web の 3D で最も情報量が多く，Claude が正確に書ける（比較は「3D ライブラリの比較」） |

## 機能ごとの実現方法 (Implementation Approach)

### VR 表示と頭の向き (Stereo Rendering)

- three.js の `StereoCamera` で左右の目の画像を作り，画面を左右に分けて描画する．レンズの歪み補正は最初は行わない（必要なら後から入れる）
- 頭の向きは `DeviceOrientationEvent` の値（alpha・beta・gamma）と画面の向きから回転を計算する
- 開始時に正面を向いた状態で向きをリセットする（ゴーグル内でボタンが押せないため，一定時間正面を見る等で行う）

### 歩行・しゃがみ判定 (Step & Squat Detection)

- **足踏み**: 上下方向の加速度の山を数え，一定間隔で山が続いている間は前進する．頭の揺れと区別するため，山の大きさと間隔にしきい値を設ける
- **しゃがみ（改善が必要）**: 加速度を 2 回積分して上下の移動量を出す方法は誤差が溜まりやすい．以下を組み合わせて精度を上げる
  - 「下向きの加速 → 減速して止まる」という動きの形で，しゃがむ・立つの動作そのものを検出し，状態（立っている／しゃがんでいる）を切り替える
  - 積分は動作中の短い時間だけ行い，静止したら速度を 0 に戻して誤差を捨てる
  - 体験開始時のキャリブレーション（PLAN_04 の S1）で，本人のしゃがみの深さ・速さに合わせてしきい値を決める
- しきい値の調整のため，センサーの値を記録して CSV で書き出す**開発用ページ**を最初に作る．記録したデータはテストの入力にも使う

### ハンドトラッキング (Hand Tracking)

- `getUserMedia`（`facingMode: "environment"`）で背面カメラの映像を取り，`HandLandmarker` に渡す
- 描画と同時に動かすと iPhone では重いため，**手の認識は 10〜15 回/秒程度に間引き**，映像も縮小してから渡す
- 判定に使うモデルファイルと wasm はリポジトリに同梱して自前で配信する（体験中に外部へ通信しないため）
- 手の 2D 座標をカメラの画角に合わせて VR 空間内の位置に変換し，手の 3D モデルを表示する．「触れる」「握る」は指先の位置と指の曲がり具合で判定する

### 音響・ナレーション (Audio & Narration)

- ナレーションは VOICEVOX（無料の日本語音声合成ソフト）で作った音声ファイルを同梱する．利用規約に従い，README 等にクレジット（`VOICEVOX:キャラクター名`）を書く
- 効果音・環境音はライセンスを確認した無料素材を使い，出典を README に書く
- ファイル形式は iPhone・Android の両方で再生できる `mp3`（または `m4a`）にする
- 火元やサイレンは `PositionalAudio` で空間に配置し，頭の向きで聞こえる方向が変わるようにする

## iPhone で注意すること (iPhone Constraints)

| 制約 | 対策 |
| --- | --- |
| WebXR が使えない | 自前の左右 2 画面描画にする（前述） |
| 傾き・加速度センサーの利用に許可が要る | 開始画面のボタンをタップした時に `DeviceMotionEvent.requestPermission()` を呼ぶ．HTTPS でないと使えない |
| 音はタップするまで鳴らせない | 同じタップで `AudioContext` を再開し，音声ファイルを読み込んでおく |
| 画面の全画面表示（Fullscreen API）が使えない | ホーム画面に追加して起動すると全画面に近い表示になる（Web アプリマニフェストを用意する）．Safari のまま横向きにしても使えるようにしておく |
| 画面の向きを固定できない | 縦向きのときは「横向きにしてください」と表示する |
| 体験中に画面が消える | Wake Lock API で画面のスリープを防ぐ（ホーム画面から起動した場合の動作は要検証） |
| エラーや `console.log` の出力を見るには，Mac の Safari をケーブルでつなぐ必要がある | 開発時だけ，iPhone のログを開発サーバーへ送ってターミナルに出す仕組みを作る（後述「実機のログの確認」） |

## 実機での確認方法 (Testing on Devices)

- カメラとセンサーは **HTTPS でないと使えない**．また WSL2 上の Dev Container で動かす開発サーバーには，同じ Wi-Fi のスマホから直接つなぐのが難しい
- そのため，開発サーバーを cloudflared の Quick Tunnel（アカウント不要．`https://〜.trycloudflare.com` の一時 URL が発行される）で公開し，スマホからその URL を開いて確認する
  - Vite 側で `server.allowedHosts` にトンネルのドメインを許可する必要がある
  - URL を知っていれば誰でも開けるため，秘密情報は置かない（静的サイトなので通常は問題ない）
- 代替: VS Code のポート転送（GitHub ログインが要る），`main` にマージ後の GitHub Pages
- 具体的なコマンドは環境構築フェーズで ENV_04 に書く

## 実機のログの確認 (Viewing Logs from Devices)

- Web アプリでも，エラーや `console.log` の出力はブラウザの中にしか出ない．PC のブラウザなら開発者ツールで見られるが，iPhone の Safari は **Mac の Safari とケーブルでつないだ時しか見られない**（Android の Chrome は Windows の Chrome からも見られる）
- このアプリではセンサーの値・判定結果・fps を見ながらしきい値を調整するため，実機のログが見えないと開発が進まない．しかもゴーグルを付けている間は画面を見られない
- そこで，**開発時だけ iPhone のログを開発サーバーに送り，ターミナルとファイルに出す**．Claude もそのファイルを読めるため，「iPhone で試す → Claude がログを読んで直す」を繰り返せる
- 画面上にログを出すツール（eruda）は，ゴーグルを外してその場で確かめたい時の補助として開発時だけ読み込む
- 本番（GitHub Pages）では，どちらも読み込まない

## 3D ライブラリの比較 (3D Library Comparison)

| 観点 | three.js | Babylon.js |
| --- | --- | --- |
| Claude が正確に書けるか | 情報量が最も多い．ただし版ごとに API が変わるため，**版を固定**し，型定義に従わせる | 情報量は three.js より少ない．後方互換を重視しており API は安定している |
| iPhone での立体視 | `StereoCamera` で自前に組む | 旧来の立体視カメラ（`VRDeviceOrientationFreeCamera`）は WebVR 時代のもので，公式フォーラムでも非推奨とされている．結局は自前で組む |
| 炎・煙・物理演算 | 外部ライブラリを足す | 本体に入っている（パーティクル，Havok 物理） |
| 読み込みの重さ | 軽い | 重い（iPhone での読み込みが遅くなる） |
| 型 | `@types/three` | TypeScript で書かれている |

Babylon.js は機能が揃っている点で有力だが，このアプリで最も難しい部分（iPhone の立体視・センサー判定・カメラの手の認識）はどちらでも自前で作る．そのため，情報量が多く軽い three.js を採用し，足りない機能だけライブラリを足す．

## 採用しなかった案 (Rejected Alternatives)

| 案 | 採用しなかった理由 |
| --- | --- |
| WebXR（three.js の `VRButton` 等） | iPhone の Safari が対応していない |
| A-Frame | WebXR 前提の作りで，iPhone では VR モードが使えない．中身は three.js であり，独自の判定処理を組み込むと結局 three.js を直接触ることになるため，層が 1 つ増えるだけになる |
| Babylon.js | 前述「3D ライブラリの比較」 |
| Unity（WebGL 出力） | iPhone の Safari では重く，ビルドに時間がかかる．エディタでの GUI 操作が多く Claude だけで作業しにくい．カメラ映像や MediaPipe とのつなぎ込みにも手間がかかる |
| React Three Fiber | VR 以外の画面が少なく，React を入れる利点が小さい |
| ブラウザの読み上げ（`speechSynthesis`） | 声が機械的で端末ごとに違う．iPhone では鳴らない場合がある |
| 音声認識（Web Speech API） | 要件で声による操作を行わないことにした |
| Vercel・Cloudflare Pages | PR ごとのプレビューは便利だが，外部アカウントの作成と連携が要る．必要になったら移行する |
