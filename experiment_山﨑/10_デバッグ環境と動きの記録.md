# デバッグ環境と動きの記録 (Debug Environment & Motion Recording)

判定をすぐに改善できるよう，動きのデータを常に記録し，記録を使って PC で再現・調整できる仕組みを作る．あわせて，**他の担当の完成を待たずに，担当D だけで開発・確認できる環境**を用意する．

## 目指す流れ (Improvement Loop)

```text
① ゴーグルで試す（フライトレコーダーが自動で記録）
  → ② 誤判定したら，見ている人が PC のキーで印を付ける
  → ③ 開発サーバーの logs/ に記録が保存される
  → ④ PC の再生ページで，印の前後の波形と判定を見る．しきい値を変えてやり直す
  → ⑤ 直したら，その場面を切り出して回帰テストに足す（Vitest）
  → ① に戻る
```

- 記録は人が読むだけでなく，**Claude も `logs/` のファイルを読める**．「iPhone で試す → Claude が記録を読んで直す」を繰り返せる（ENV_01「実機のログの確認」と同じ考え方）

## フライトレコーダー (Flight Recorder)

開発時だけ読み込み，体験中ずっと動かしておく記録の仕組み．

### 記録するもの (What to Record)

| 種類 | 中身 | 頻度 |
| --- | --- | --- |
| センサーの生の値 | `timeStamp`・`acceleration`・`accelerationIncludingGravity`・`rotationRate`・`interval` | `devicemotion` ごと（約 60 Hz） |
| 向き | `alpha`・`beta`・`gamma`・`screen.orientation.angle` | `deviceorientation` ごと |
| 判定の途中の値 | 上下の加速度・帯域通過後の値・しきい値・積分中の `Δh`・学習モデルの出力 | サンプルごと |
| 判定の結果 | `posture`・`walking`・`walkSpeed`・状態機械の状態の変化 | 変化した時 |
| 手 | 21 点 × 2 手・`tracked`・形の判定 | 認識ごと（10〜15 回/秒） |
| 処理時間 | フレームの間隔・各処理の時間 | フレームごと |
| 文脈 | 端末の情報・`CalibrationProfile`・使ったしきい値（`params`）・今の画面とシナリオの段階 | 変化した時 |
| 印 | 見ている人が付けた印（誤判定の種類） | 押した時 |

- **カメラの映像そのものは残さない**（大きさとプライバシーのため）．手は 21 点の座標だけ残す．映像が必要な時だけ，dev ページで低解像度・低頻度の保存を選べるようにする
- 大きさの目安: 1 分で約 1〜2 MB（JSONL のまま）．3 分の体験で数 MB

### 保存のしかた (Storage)

- 記録はメモリ上のバッファにため，**2 秒ごとに開発サーバーへ送る**
- 開発サーバーは受け取った記録を `logs/input/<日時>_<セッション ID>.jsonl` に追記する（`logs/` は `.gitignore` 済み）
- 1 行に 1 つの記録（JSONL）．途中で落ちても，そこまでの記録は残る
- 送れない時（開発サーバーにつながっていない等）は IndexedDB にためておき，後で dev ページからダウンロードできるようにする
- 本番（staging・本番）では読み込まない

### 印の付け方 (Marking)

ゴーグルを付けた本人は画面に触れられないため，**見ている人が PC から印を付ける**．

- PC のブラウザで開く「操作盤のページ」で，キーを押すとその時刻に印が付く（例: `1` 歩いていないのに進んだ，`2` 歩いたのに進まない，`3` 立っていないのに立った，`4` 手が震えた・消えた，`Space` その他）
- 印は開発サーバーを経由して，記録に同じ時刻の基準で書き込まれる（スマホと PC の時計のずれは，接続した時に一度合わせる）
- 本人だけで試す時のために，体の動きでも印を付けられるようにする案もある（例: 背面カメラを手で 1 秒覆う）．誤って付くと困るため，dev ページで有効にした時だけ使う

### 開発サーバーで受け取る口 (Dev Server Endpoint)

- Vite の開発サーバーに，記録を受け取る口（`POST /__input-log` 等）を足す小さなプラグインを作る．プラグインの本体は `src/input/dev/` に置き，`vite.config.ts` には登録の 1 行だけ足す
- `vite.config.ts` は全員で使う設定のため，**足す時は小さい専用の PR にし，全員に知らせる**
- ENV_01「実機のログの確認」（`console.log` を開発サーバーへ送る仕組み）と同じ仕組みでできるため，**誰が作るかを Issue で調整し，1 つにまとめる**．先に作るなら，ログの転送にも使える形にしておく
- 開発サーバーの起動等のコマンドが増えた時は ENV_04 に書く

## 記録の再生 (Replay)

### 再生と調整のページ (Replay & Tuning Page)

PC のブラウザだけで使う．

- `logs/input/` の記録を読み込み，判定の純粋な関数に**もう一度通す**（記録した結果を見るだけでなく，今のコードで判定し直す）
- 波形（上下の加速度・帯域通過後の値・しきい値・`Δh`）・判定の結果・手順のラベル・印を，同じ時間軸に重ねて表示する
- しきい値をスライダーで変えると，すぐに判定し直して結果が変わる．変える前と後の判定を並べて表示する
- SPEC の指標（誤検出の回数・見逃しの割合・動き出しの遅れ）を記録ごとに集計して表示する
- 決めたしきい値は `params` の JSON として書き出し，`src/input/` の既定値に反映する

### 回帰テストへの切り出し (Promoting to Regression Tests)

- 誤判定した場面を前後数秒で切り出し，`src/input/__fixtures__/` に置く（大きくしないよう，必要な列だけ残す）
- 切り出した記録に「期待する判定」（例: この区間は `walking: false`）を付け，Vitest で確かめる
- しきい値を変えた時に，過去の誤判定が戻ってこないことを自動で確かめられる（SPEC「記録データでの再現テスト」）

## 自分だけの dev ページ群 (Standalone Dev Pages)

`src/input/dev/` に置く．Vite の開発サーバーは HTML を直接配信するため，ビルドの設定（`vite.config.ts` の入口）を変えずに `/src/input/dev/<ページ>.html` で開ける．本番のビルドには含まれない．

**依存は `core/` と three.js だけにし，scenes/・render/・scenario/・lobby/ に依存しない**．他の担当の作業の進み具合や変更に左右されずに開発できる．

| ページ | 使う端末 | 内容 |
| --- | --- | --- |
| センサーの確認 | スマホ | センサーの値・判定の途中の値・状態をグラフと数値で表示する．しきい値をその場で変えられる．フライトレコーダーも動かす |
| 手順の記録 | スマホ（ゴーグル） | 決まった手順を音声と表示で案内し，**案内した時刻からラベルを自動で付けて記録する**（[06](06_学習モデルとUCI_HAR切り分け実験.md)・[11](11_検証計画.md)） |
| ゴーグルでの確認 | スマホ（ゴーグル） | 最小限の左右 2 画面の空間（床の格子・距離の目安の柱・目の高さの線・手の球と指先の点）．歩く・しゃがむ・手を動かした時の感覚だけを確かめる．scenes/ の部屋も render/ の描画も使わず，`StereoCamera` で自前に描く |
| 手の確認 | スマホ | カメラの映像に 21 点・形の判定・遅れを重ねて表示する．One Euro のパラメータをその場で変えられる |
| 再生と調整 | PC | 上記「再生と調整のページ」 |
| 操作盤 | PC | 印を付ける．スマホの判定の状態を PC で見る（開発サーバー経由） |

- スマホから開く時は `npm run tunnel` の URL に `/src/input/dev/<ページ>.html` を付ける
- 各ページのしきい値は URL パラメータでも渡せるようにし，同じ設定を QR コードで他のメンバーの端末に配れるようにする

## PC 用のモック入力 (Mock Input)

- SPEC_01「開発時の独立性」のとおり，キーボードとマウスで `PlayerInput` を作るモック入力も `src/input/` に置く（W／A／S／D で歩く，C でしゃがむ，マウスで頭の向きと手，クリックで握る）
- さらに，**記録を再生して `PlayerInput` を作るモック**も用意する．他の担当は，実機の動きのとおりの入力で部屋やシナリオを確かめられる（例: 「しゃがんだまま 30 秒」の記録を流す）
- いずれも `app/` で本物の入力と切り替えられるよう，同じ形（`PlayerInput` を返す関数）にする
