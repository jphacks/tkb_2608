# 担当D（input/）技術設計メモ (Input Module Design Notes)

担当D（`radio2400727`）が受け持つ `src/input/` について，**遅延をなくす・計算量を抑える・動作を安定させる（UX）** ための技術方針を Claude と相談した結果をまとめる．
正式な仕様ではなく相談の記録である．決まったものは後で `docs/04_SPEC/`・`docs/05_TECH/` に移し，実装は `/implement` で `src/input/` に作る．

**本書の数値はすべて目安である**．Day 1 以降の実機検証で実測し，見直す．

## 前提 (Premises)

- シナリオ: [PLAN_04「シナリオ」](../docs/03_PLAN/PLAN_04_要件定義書.md)（地震．家 H1・電車 T1／T2・エレベーター E1／E2 の全 5 種類）
- 担当と受け渡すデータ・処理時間の予算・判定の安定性の指標: [SPEC_01](../docs/04_SPEC/SPEC_01_画面遷移とモジュール構成.md)

- 型の実体: `src/core/types.ts`（`PlayerInput`・`HandState`・`CalibrationProfile`）

## 決定事項 (Decisions)

| 論点 | 決定 | 詳しくは |
| --- | --- | --- |
| 処理の駆動 | センサーのイベントが届くたびに O(1) で状態を更新し，描画のループは最新の状態を読むだけにする．判定は純粋な関数，購読は薄い殻 | [02](02_全体アーキテクチャ.md) |
| 頭の向き | クォータニオンで扱い，描画の直前に読み込む．ジャイロで短く先読みする．平滑化はほぼしない | [03](03_頭の向きと見回し.md) |
| 歩き・しゃがみ・立ち上がり | **ハイブリッド方式を基本にする**．動き出し・止まりは信号処理で低遅延に判定し，学習モデルは「歩きの誤検出の除去」と「しゃがみ・立ち上がりの波形の見分け」に使う | [04](04_足踏み.md)・[05](05_しゃがみ_立ち上がり_しゃがみ歩き.md) |
| UCI HAR の利用 | **決めつけず，最初に切り分ける**．公開データで学習したモデルがゴーグル装着時のデータにそのまま使えるかを，判定基準を決めて確かめる．使えれば自前の学習が要らない | [06](06_学習モデルとUCI_HAR切り分け実験.md) |
| しゃがみ歩き | 判定の対象にする．姿勢（立つ／しゃがむ）と移動（歩く／止まる）を独立した 2 つの軸にする | [05](05_しゃがみ_立ち上がり_しゃがみ歩き.md) |
| 階段 | 判定しない．SPEC どおり足踏みとして扱う | [04](04_足踏み.md) |
| 手の位置のなめらかさ | **One Euro フィルタ＋短い外挿**．SPEC・ENV_01 の「線形補間」からの変更として提案する | [07](07_ハンドトラッキングと手の動作.md) |
| つかむ等の判定の担当 | **手の形（握る・つまむ・指を差す）とその安定性は担当D**．**手と物の組み合わせ（何をつかんだ・押した・回した）は担当B** | [07](07_ハンドトラッキングと手の動作.md)・[12](12_他担当への依頼と提言.md) |
| 動きのデータの保存 | 開発時は常に記録する（フライトレコーダー）．開発サーバーの `logs/` に自動で保存し，すぐに再生・調整・回帰テストに使う | [10](10_デバッグ環境と動きの記録.md) |
| 自分だけのデバッグ環境 | `src/input/dev/` に，他の担当のコードに依存しない dev ページ群を作る（使うのは `core/` と three.js だけ） | [10](10_デバッグ環境と動きの記録.md) |

### ユーザー案への見解 (Review of the Initial Proposal)

| 案 | 見解 |
| --- | --- |
| 歩行・行動推定を UCI HAR／WISDM 由来の 1D-CNN で行う | 推論が軽い点はその通り．ただし，データの取り方が違う（腰・ポケット・手首）・窓が長い（2〜2.5 秒）ため遅れる・しゃがみの分類が無い，の 3 点が懸念．**まず使えるかを切り分ける**（[06](06_学習モデルとUCI_HAR切り分け実験.md)） |
| MediaPipe Hands | 旧版は非推奨．Tasks Vision の `HandLandmarker` を使う（ENV_01 どおり） |
| 解像度の縮小・間引き | 採用する．間を埋める処理は線形補間ではなく One Euro＋外挿にする（遅れが約 100 ms → 約 20 ms） |
| 当たり判定に Three.js／Unity の物理エンジンや Raycast | 担当B（scenes/）の担当．物の数が少ないので，three.js での距離の判定で十分．Unity は使わない |
| 描画に WebXR／A-Frame／Unity | iPhone の Safari が対応していないため ENV_01 で不採用．`StereoCamera` で自前に描画する |
| 録画を一時ストレージに保存 | 担当A の担当．SPEC は「端末のメモリ上だけに持つ」としているため，食い違いを担当A と相談する |
